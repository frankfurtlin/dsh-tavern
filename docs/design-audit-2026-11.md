# 酒馆视觉与体验评审（2026-11-18）

对象：`/tavern/` 当前生产版本（提交 `6ac7741`）。方式：桌面 1440×900、移动 390×844 实机截屏 + 样式变量与模板核对。

截图：`docs/screenshots/design-audit-2026-11/`

---

## 一、总体判断

骨架（信息架构、字号层级、触控尺寸、空态/错误态）已经比同类自建产品干净，问题不在"能不能用"，而在**气质不统一**：

- 底色 `#F6F7F9` + 白卡 + 焦橙 `#B45A24` + 衬线标题，组合出来是**SaaS 后台**；内容却是角色扮演与长文叙事。
- 同一个页面里出现两种"产品"：角色详情像**配置表单**（textarea 填 prompt），聊天页像**IM**（气泡 + 时间戳），卡库像**卡片管理**。三套隐喻没有统一到"阅读/扮演"这件事上。
- 装饰少、留白多是对的，但**该有氛围的地方没有（聊天/详情），该克制的地方又很吵（首页两条提示条、三层标题、四组按钮）**。

一句话：**降噪 + 找回"故事感"。**

## 三、审美层面的问题（P1：气质与阅读体验）

### 3.1 角色卡库（`d1b-characters.webp`）

- 1440 下 3 列、5 张卡留出大片死区，网格没有节奏。→ `auto-fill minmax(280px,1fr)`，或首行做一张 2 列宽的"主推进"大卡打破均质。
- 顶部到列表之间有 5 层横向元素：搜索、聊天历史、导入卡、提示条、多选条。→ 提示条并入空态/一次性 toast；「聊天历史」降级为图标按钮或并进标题栏。
- 品牌「酒馆」+ 居中「角色卡」+ 右上齿轮 = 三个焦点。→ 标题左对齐成「酒馆 / 角色卡」面包屑，居中标题让位给内容。
- 头像右下角橙色小圆点（酒馆 logo 的 dot）在通知语境里会被读成"未读"。→ 缩小或去掉。

### 3.2 聊天页（`d5d-reply.webp`、`m4b-chat.webp`）

- **动作描写不渲染**：`*自己先笑出声，从板凳上跳下来。*` 原样带星号，和正文同色同字号；长回复像一堵墙。→ 纯文本安全切分，`*…*` 渲染为斜体 + `--quiet` 色，段落间距 12→14；行高 1.8→1.9。
- **引号混排**：`"来了。"` ASCII 直引号 + 中文正文。种子卡可做一次「成对 ASCII 引号 → “ ”」规范化（仅预设资产，不动用户输入）。属可选打磨。
- **气泡配色过甜**：助手气泡 `#FFF2E8` 大面积铺满屏，用户气泡焦橙，长聊后整屏发橙。→ 助手气泡改白底 + 1px `--edge`，只有用户气泡着色；群里再给每位角色一个低饱和描边色。
- **群聊识别弱**：只有 22px 头像 + 12px 名字飘在气泡上方（`d7d-group.png`），主次不清。→ 气泡左加 28px 固定头像槽，speaker 名字与头像同行，气泡左对齐缩进；单聊不显示。
- **时间戳/操作条**：时间 10px 灰塞在气泡内底部；操作（引用/重新生成/删除）常驻；用户气泡上的「你」10px 白字压在橙底上对比不足。→ 时间移出气泡、按天分隔（今天/11月17日），操作行 hover/长按才出现，"你"删除。
- **顶栏图标不同源**：`?` 是文本字符，搜索/下载是 16px 线性图标；群聊「管理成员」藏在下载菜单里，几乎发现不了。→ 全部换 Lucide；群聊头部直接放可点的成员头像堆叠。
- **空态太素**：群聊只有一句「还没有消息，说点什么开始吧。」（`d7d-group.png`）。→ 显示成员头像 + 「唐团团 会先开口」+ 一句引导示例。

### 3.3 设置与帮助（`d6-settings.png`、`m6-settings.webp`、`d7-help.webp`）

- 「预设」标题出现两次；「人设（我是谁）」+ 卡内「我是谁」再重复；「当前人设 / 默认人设」两个下拉语义割裂。→ 合并成「我的人设：当前使用 / 新聊天默认」一个区块。
- 参数是开发者口吻：`temperature 0.8 · top_p 0.95 · max_tokens 1024`。→ 「温度 0.8 · 采样 0.95 · 上限 1024 tokens」+ tooltip。
- 移动端吸底主按钮是「返回角色卡」——把导航做成主 CTA，页面上也没有"保存"。→ 返回降级为文字/图标，主按钮留给"保存"（若有未保存改动）。
- 帮助页 7 节纯文本，无目录。→ 桌面左侧目录、移动顶部 chips 跳转。

### 3.4 设计系统不一致

- 圆角 8/9/10/12/14/16/20 六档混用 → 收敛为 10（控件）/14（卡片）/20（弹层）三档。
- 颜色：同一个橙在正文、按钮、徽标、描边里出现，但小字用同一橙导致对比不足；缺一个 `--accent-ink`（深赭，专供小字）。
- 字体：标题 `--font-serif` 依赖本机是否装 Noto Serif SC/Songti，容器截图里实际回退成无衬线 → 跨设备层级不稳定。→ 自托管子集字体（Noto Serif SC 600 + Regular），或明确接受无衬线并把标题换成 `font-weight:650 + letter-spacing`。
- 图标：Lucide + 文本字符（`?`、`×`、`⋯`）混用 → 统一 Lucide。
- 动效：气泡出现、页面切换、弹层全是瞬移 → 120–160ms ease-out 的最小集即可显著提升质感。
- 无障碍：触控 36/40px 目标若干（历史行、清空搜索）；focus ring 不可见；`?` 按钮 44 达标但图标不达标。

## 四、两个方向（选一个再动手）

**A. 暖纸本（推荐）** —— 保留现在的克制，把"后台灰"换成"纸感暖调"：

```
--paper   #FAF7F2   --canvas #FFFDF9
--ink     #2B2622   --quiet  #6B6158
--edge    #E7E0D4   --wash   #F6EEE3
--accent  #8C4A2F   --accent-ink #7A3E27
```

标题衬线、正文 16px/1.9；聊天页背景带极淡纸纹（CSS radial 2% 不透明度）；助手气泡白底描边，用户气泡深赭。改动集中在 token + 聊天/详情两页，风险低、见效最快。

**B. 极简留白** —— 保持冷灰，但把橙色降到只用于主 CTA 与选中态，其余中性；聊天区做成"文档流"（无气泡、头像+名字+正文），更像阅读器而不是 IM。

## 五、建议顺序

1. **P0 八项**（缺陷 + 低成本修正，CSS/模板级）
2. **方向落地**：token 重设 + 字体加载 + 角色卡库网格/操作收拢
3. **聊天阅读**：动作斜体、日期分隔、hover 操作、群聊 speaker、气泡配色
4. **详情页**：只读/编辑分离、hero 立绘、标签 chips
5. **系统化**：圆角/图标/动效/焦点环，补一组视觉回归截图

每步仍按既有约束：隔离全量 E2E + 生产冒烟，可回滚到当前 `6ac7741`。
